# 协议与验证范围

## 授权

中国福特派使用 B2C 授权码交换 DLT 凭证。交换 `policyType` 为
`SIGNINSIGNUP`。代码先保存交换后的凭证再请求车辆列表，避免暂时的
车辆查询失败浪费一次性授权码。当前观测访问凭证有效期约 30 分钟、
刷新凭证约两小时；以后以响应中的期限为准。访问期限临近或刷新凭证
剩余不足 45 分钟时主动续期，续期过程逐账号串行并持久化响应。

白盒加密的 IV 使用 16 个随机小写 ASCII 字母，并编码成十六进制。
原生 codec 依赖单独提供的官方客户端文件，仓库中只提供适配代码。

## 基础车况与车锁

基础查询采用 R3 签名。车锁通过 `send-command` 提交 `DoorLock`／
`DoorUnlock`，得到 UUID 命令号后查询 `command-execution-status`。
解密正文中 `552` 表示执行中、`200` 表示完成，随后读取车况确认目标
锁态。同车指令串行；请求和查询每次重新加密 VIN。超时报告结果未知，
不自动重发。不实现发动机启动或位置触发的自动车控。

## 独立定位

先调用 `third-party-token` 获取 LBS token，再调用
`https://api-connect.ford.com.cn/lbs-map/v2/public/app/queryLocation`。
请求包含加密 VIN、IV、token、source 和 secretVersion。定位使用
`lbs_p2c` codec 与独立签名，不是基础车况接口里的 GPS 字段。

LBS 签名是拼接 secret、排序参数、timestamp、payload key 及截取字段
后计算 SHA-256，再 Base64 编码并**将整个结果转大写**。只做普通 Base64
会导致签名不匹配。7 条已授权成功请求和响应校验匹配后，又使用独立
客户端成功查询。响应签名在解密坐标前校验。

## 时间与坐标

`checked_at` 表示查询开始，`last_success_at` 表示本地完整校验成功，
`reported_at` 来自车辆位置上报（当前观测为北京时间）。重复查询可以
返回同一位置。基础 `last_updated` 只在状态变化时更新，不能据此推断
轮询是否运行。分别查看定位查询状态及上报时间。

会拒绝非法或非有限坐标、零坐标、明显未来的时间及倒退的位置上报。
定位失败不会让基础车况整体失败；当前位置与距离变为 unavailable，
旧上报及最后成功时间仍可检查。原始坐标系尚未独立核实，距家按整
公里提供近似直线距离，不应当作导航里程或到家自动化依据。

## 测试

单元及协调器测试均采用合成数据，不调用真实车控。已验证基础授权、
自然过期续期、定位独立查询和随后定时查询；锁车实机协议证据来自
车主在官方 App 的操作。各车型、海外账号、HA OS 和 x86 codec 尚未
形成完整兼容矩阵。请勿把当前能力标为与官方 App 完全等效。
